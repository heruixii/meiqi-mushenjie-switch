# 字体审计结果

更新时间：2026-09-01

## 结论

- 标准 `.fnt` 的元数据为 12 字节字形记录，记录内容为有符号定位、宽高和字形数据偏移。
- 标准字体的字形位图数据按 `宽 × 高 × 2` 字节存储；元数据和偏移检查通过。
- `k_minamotomakotogoshikkutouhabanormal_20x20.fnt` 是 `FNT DATA VER-` 特殊格式，已单独标记，不能按标准头解析。
- `system16.fnt`、`system24b.fnt`、`system32.fnt` 各有 1548 条相同特征的缺字占位记录；这说明不能仅凭 `.fnt` 缓存判断所有中文都能显示。
- 原来的审计只统计原文列，不能证明译文字符有字形；现已改为同时统计原文和译文列。
- 重新审计必须使用包含实际译文的表格，重点检查新增中文字符是否有 cmap 映射。
- 对当前最小测试表的检查结果：三个 TTC 均覆盖“界”和“间”；测试译文中缺少“标、题、开、头”。
- 这项结果只说明 TTC 的 cmap 映射，不能单独证明运行时使用的 FNT 缓存一定能显示这些字；实机仍需验证。

## 当前策略

第一章译文包含大量游戏 TTC 未收录的简体字。此前仅增加繁体字形别名会导致“编码是简体、外观仍像繁体”。当前构建脚本改为将所有译文中的汉字和中文标点直接映射到 `C:\Windows\Fonts\simhei.ttf` 的简体字形，并保留游戏字体的字号、字宽和其他原有字形。字体补丁只输出三份 TTC，不改动原有 `.fnt` 文件；重新构建时需要保留该字体源文件。

当前补丁的离线覆盖检查为 2829 个字符、缺字 0 个，其中 902 个译文非 ASCII 字符使用简体中文字体字形。最终仍需在 Switch 实机确认字形比例和所有文本框的换行效果。

详细机器可读结果见 `docs/font-audit.tsv`，生成脚本为 `06_scripts/analyze_fonts.py`。
